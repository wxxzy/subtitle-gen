# 08 · 去除视频自带字幕

> **本篇目标**：去掉素材里已经烧进画面的字幕，避免新老字幕重叠。
> **前置知识**：知道 ffmpeg 的滤镜链（`-vf`）。
> **对应代码**：`subgen/desub.py`（476 行）
> **耗时**：35 分钟。

---

## 1. 本篇要解决的问题

场景很具体：**手上有带字幕的老素材，要重新做一版字幕**。

不处理会怎样？

```
┌─────────────────────────┐
│                         │
│        （画面）          │
│                         │
│  男牵着双马尾女友走出电梯  │  ← 原字幕
│  The man walks out with  │  ← 新字幕
│      his girlfriend     │
└─────────────────────────┘
```

**两行字幕叠在一起，完全没法看。**

---

## 2. 先分清两种情况

这一步很重要，因为**处理方式完全不同**：

| 类型 | 能否真正删除 | 怎么做 |
|---|---|---|
| **软字幕**（独立字幕流） | ✅ 可以 | `ffmpeg -sn` 直接剥离，画质无损 |
| **硬字幕**（烧进画面像素） | ❌ 只能遮盖 | 把字幕区糊掉 |

### 怎么判断

```bash
ffprobe -v error -show_streams 你的视频.mp4 | grep codec_type
```

如果输出里有 `codec_type=subtitle`，就是软字幕。

**软字幕处理极其简单**：

```bash
ffmpeg -i 输入.mp4 -sn -c copy 输出.mp4
```

`-sn` = 丢弃字幕流，`-c copy` = 不重新编码。**一秒完成，画质零损失。**

> ⚠️ **先检查这一步**。很多"要去字幕"的诉求其实是软字幕，
> 根本不需要本篇的复杂方案。

### 硬字幕的固有限制

**这是个必须说清楚的事实**：

> 硬字幕已经烧进像素了。**原始画面信息不存在了**——
> 被字幕覆盖的那部分画面，在任何地方都没有备份。

所以「去除」这个词严格来说不准确，应该叫「遮盖」。
能做到的上限是"让人看不出这里有字幕"，而不是"还原出原来的画面"。

---

## 3. 核心概念：四种方案实测对比

我试了四种遮盖方式，**结果和直觉完全相反**。

测试条件：720×1280 竖屏，字幕带 691×68 像素，粗体白字带描边。

| 方案 | 命令核心 | 结果 |
|---|---|---|
| **delogo** | `delogo=x:y:w:h` | ❌ **出现规则竖向条纹，比原字幕还难看** |
| **boxblur** | `boxblur=13:1` | ⚠️ 糊不透，字迹依然清晰可读 |
| **drawbox** | `drawbox=...:color=black@0.85` | ❌ 白字在黑条上更显眼 |
| **降采样+放大** | `scale=17:2,scale=691:68` | ✅ **字迹完全糊掉，观感自然** |
| pixelate | `scale→小→scale→neighbor` | ✅ 最彻底，但马赛克风格明显 |

### 为什么 delogo 会失败（这是本篇最值得记的）

`delogo` 是 ffmpeg 官方的"去水印"滤镜，**看起来应该是首选方案**。

我的第一版代码就是用它写的。跑完一看：

```
┌──────────────────────────────────┐
│ ▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏▏ │  ← 竖向条纹
└──────────────────────────────────┘
```

**比原字幕还难看。**

**原因**：`delogo` 的原理是**用区域四周的边缘像素做插值填充**。

```
    ↑ 上边缘
  ← [ 字幕区 ] →     ← 左右边缘
    ↓ 下边缘
```

在**窄条**（比如台标，几十像素宽）上，四周像素颜色接近，插值结果很自然。

但字幕带**很宽**（691 像素），左右两侧的采样点跨度太大：

```
左边像素（暗） ......... 691px ......... 右边像素（亮）

插值 → 从暗到亮的渐变条纹
```

**结果就是规则的竖向条纹。**

> 💡 **教训**：官方滤镜 ≠ 适合你的场景。
> 一定要用**真实素材**试，不能看文档就下结论。

### 为什么 boxblur 也不够

```python
# 第一次尝试
boxblur=16:1
```

报错：

```
Invalid chroma_param radius value 16, must be >= 0 and <= 13
```

**`boxblur` 的色度半径上限只有 13**（不是文档常说的 18）。

改成 13 之后能跑了，但效果：

```
┌──────────────────────────┐
│ 男牵着双马尾女友走出电梯     │  ← 还是能认出来
└──────────────────────────┘
```

**13 像素的模糊半径，扛不住这种粗体大白字。**

### 最终的解法：降采样

```python
div = 40
bw = max(2, w // div)      # 691 // 40 = 17
bh = max(1, h // div)      # 68 // 40 = 1
f"crop={w}:{h}:{x}:{y},scale={bw}:{bh},scale={w}:{h}:flags=bilinear"
```

**把 691×68 的区域先缩到 17×1，再放大回来。**

等效于**极其强烈的模糊**——1 个像素高度意味着整行被平均成一个颜色，
字迹彻底消失。但因为有 17 个宽度采样点，还保留了**左右方向的明暗过渡**，
所以看起来像自然的虚化，而不是一块纯色。

**这就是它比纯色块好看的原因。**

> 💡 **一个实用的思路**：当 ffmpeg 内置滤镜的参数受限制时，
> **可以用 `scale` 降采样来模拟"超参数"的效果**。
> 缩得越小，等效模糊越强，上限由你决定。

## 4. 核心概念：自动定位字幕

遮盖需要具体的像素坐标，但用户不知道怎么量。

### 思路：找"高亮密集的横向条带"

硬字幕的特征：**白字 + 描边**，会在某一行密集出现高亮像素。

```python
def _frame_row_profile(im, threshold: int) -> List[float]:
    """单帧的逐行"文字特征强度"。"""
    if threshold <= 0:
        # 自适应阈值：取全帧亮度的高分位
        hist = im.histogram()
        total = sum(hist)
        acc = 0
        for v in range(255, -1, -1):
            acc += hist[v]
            if acc >= total * 0.03:      # 最亮的 3%
                threshold = max(150, v)
                break

    prof = []
    for y in range(H):
        c = sum(1 for x in range(0, W, 2) if px[x, y] > threshold)
        prof.append(float(c))
    return prof
```

### 关键设计一：自适应阈值

**为什么不用固定的 235？**

我第一版就是这么写的，结果：

| 素材 | 固定阈值 235 的结果 |
|---|---|
| 暗色室内 | 检不出（字不够亮） |
| 蓝天背景 | **误判**（天空很亮） |
| 白色衣服 | **误判**（衣服很亮） |

**改成"取该帧最亮的 3%"，就能适应不同亮度的画面。**

### 关键设计二：优先取最靠下的条带

```python
# 多个候选带时**优先取最靠下的那个**。
#
# 为什么不是"取最长的"（早期版本的坑）：实测白猫的高光区、
# 浅色衣服的亮部都会形成密集带，且往往比字幕带更大更长。
# 但台词字幕几乎总在画面下方 —— 这个先验比"谁更长"可靠得多。
bottom_run = max(runs, key=lambda r: r[1])
```

**这个细节很说明问题。**

第一版我用的是"取最长的条带"，因为直觉上字幕应该是最显著的特征。

实测：

```
视频 1（白猫）：猫脸高光区 长度 100，字幕带 长度 68
              → 选了猫脸 ❌
```

**白猫的毛发高光，在灰度上和白色文字无法区分。**

后来改成"取最靠下的"——因为**台词字幕几乎总在画面下方**。
这个先验比"谁更长"可靠得多。

### 关键设计三：返回置信度

```python
@dataclass
class DetectResult:
    region: Optional[Region]
    confidence: float = 0.0        # 0~1
    reason: str = ""
    candidates: List[Region] = ...
```

**为什么不直接返回一个区域？**

因为**检测可能不准**。实测 5 个视频：

| 视频 | 检出位置 | 置信度 | 判断 |
|---|---|---|---|
| 1 | 68.3% | 0.70 | 准确 |
| 2 | 46.7% | 0.62 | 偏上，可疑 |
| 3 | 68.8% | 0.72 | 准确 |
| 4 | 30.2% | 0.57 | 偏上，可疑 |
| 5 | 69.2% | 0.65 | 准确 |

**3 个准确、2 个可疑，置信度确实反映了可信程度。**

所以界面上会提示：

```
置信度 0.45（条带位置偏上，可能不是字幕）
建议：请在预览中确认位置是否准确
```

> 💡 **"说不准就说不准"比强行给个错答案好。**
> 一个自动功能如果 20% 的情况会错，**必须让用户知道哪 20%**。

## 5. 代码走读：处理流程

```python
def remove_subtitles(src, dst, regions, *, method="blur", encoder="auto",
                     crf=20, preset="veryfast", strength=0, copy_audio=True):
    ff = FFmpeg()
    w, h = ff.video_size(src)
    vf = build_filter(regions, method=method, frame_w=w, frame_h=h, strength=strength)

    enc = _pick_encoder(ff, encoder)
    cmd = [ff.ffmpeg, "-i", src, "-vf", vf]

    if enc == "h264_nvenc":
        cmd += ["-c:v", "h264_nvenc", "-preset", "p4", "-cq", str(crf)]
    else:
        cmd += ["-c:v", "libx264", "-preset", preset, "-crf", str(crf)]

    cmd += ["-pix_fmt", "yuv420p"]
    cmd += ["-c:a", "copy"] if copy_audio else ["-c:a", "aac"]
    # 保留原始元数据里的旋转信息（竖屏视频很依赖这个）
    cmd += ["-map_metadata", "0", "-movflags", "+faststart", dst]
```

### 三个容易忽略的细节

**① `-pix_fmt yuv420p`**

不加这个，某些播放器会拒绝播放（因为编码器可能选了 `yuv444p` 等非标准格式）。
**这是兼容性的保险。**

**② `-map_metadata 0`**

**竖屏视频非常依赖这个。**

手机拍的竖屏视频，实际存储是横的（1920×1080），靠元数据里的
"旋转 90 度"标记来显示成竖屏。

如果不保留元数据，输出就变成横的了——**画面整个歪掉**。

**③ `-movflags +faststart`**

把索引（moov atom）移到文件头，让播放器能**边下边播**。
对本地文件无所谓，但上传到平台后影响首屏加载速度。

## 6. 两种输出模式

```bash
# 只出干净视频（推荐）
subgen.bat 视频.mp4 --desub auto --desub-only

# 一步到位出成片
subgen.bat 视频.mp4 --desub auto --burn
```

| 模式 | 产出 | 适合 |
|---|---|---|
| `--desub-only` | 干净视频 + 单独的 srt | **推荐**。画质无损、字幕可改 |
| `--burn` | 烧录好字幕的成品 | 平台只认硬字幕时 |

**为什么推荐前者？**

- 不再二次编码（`--desub` 已经编码一次了，`--burn` 又要一次）
- 字幕随时能改，改了重新挂载即可
- B站/YouTube 都支持软字幕

## 7. 一个必须说清楚的限制

**遮盖效果取决于背景。**

| 背景 | 效果 |
|---|---|
| 纯色墙、虚化背景、大片天空 | 几乎完美，看不出痕迹 |
| 人脸、细密纹理、复杂图案 | 会有可见的痕迹 |

**这是遮盖的物理极限**——你没有原始像素，只能用周围信息"猜"。

如果有人告诉你"能完美去除硬字幕"，要么是在说软字幕，
要么是在用 AI 修补（inpainting）——那需要额外的模型和时间，
而且效果也不完美。

> 💡 **诚实地说明限制**，比让用户满怀期待然后失望要好。

## 8. 动手练习

**练习 1：先判断是不是软字幕**

拿一个带字幕的视频：

```bash
ffprobe -v error -show_streams 视频.mp4 | grep codec_type
```

如果有 `subtitle`，试试：

```bash
ffmpeg -i 视频.mp4 -sn -c copy 无字幕.mp4
```

**一秒完成，画质无损。** 这一步能解决大部分需求。

**练习 2：对比四种遮盖方案**

```bash
subgen.bat 视频.mp4 --desub "14,874,691,68" --desub-only
```

然后用 Python 生成四种方案的对比图：

```python
from subgen.desub import Region, build_filter
import subprocess

g = Region(14, 874, 691, 68)
for m in ("blur", "pixelate", "delogo", "box"):
    vf = build_filter([g], method=m, frame_w=720, frame_h=1280)
    subprocess.run(["ffmpeg", "-y", "-ss", "12", "-i", "视频.mp4",
                    "-vf", vf, "-frames:v", "1", f"{m}.png"])
```

**亲眼看看 delogo 的竖向条纹。** 这个印象会让你以后不再盲信官方滤镜。

**练习 3：验证检测的置信度**

```bash
subgen.bat 视频.mp4 --desub-preview
```

多试几个视频，观察置信度和实际准确度的关系。

**练习 4：测试竖屏旋转是否保留**

用一个手机拍的竖屏视频：

```bash
subgen.bat 竖屏.mp4 --desub bottom --desub-only
ffprobe -v error -show_streams 竖屏.clean.mp4 | grep rotation
```

确认旋转标记还在。**没有的话画面会歪。**

## 9. 小结

**三句话**：

1. **先判断软/硬字幕**——软字幕 `-sn` 一秒搞定，硬字幕只能遮盖
2. **delogo 在宽区域会出竖向条纹**（边缘插值跨度太大），
   正确做法是"降采样+放大"做超强模糊
3. 自动检测要返回**置信度**，让用户知道什么时候该手动核对
