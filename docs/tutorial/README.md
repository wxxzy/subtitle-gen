# 从零构建一个字幕生成工具 · 系列教程

这是一套**按学习路径组织**的教程，不是使用手册。

使用手册告诉你「按哪个按钮」；这套教程告诉你「为什么这么设计、踩过哪些坑、当时怎么想的」。
如果你只想尽快用起来，直接看根目录的 [README.md](../../README.md)。

---

## 这套教程适合谁

| 你是 | 建议读法 |
|---|---|
| **想看懂一个真实项目怎么搭** | 从头顺读，每篇都要动手跑一遍 |
| **想自己做一个类似工具** | 重点读 02/04/05/10/11，这五篇是骨架 |
| **只想改某个功能** | 跳到对应模块篇，再回来补 02（架构） |
| **纯使用者** | 不用读，看 README 就好 |

**前置要求**：会写 Python（读懂函数、类、typing 标注即可），知道 ffmpeg 是什么。
听说了 faster-whisper 更好——会讲。
不需要事先懂音频处理、不需要懂前端框架。

## 学习路径

整个项目约 9700 行代码（Python 6470 + 界面 3249），一次读完不现实。
按下面四个阶段推进，每个阶段都能独立产出可见成果。

### 🌱 第 0 阶段 · 打地基（约 1 小时）

先跑起来、先看懂全局，不要急着钻细节。

| # | 篇目 | 你会得到 |
|---|---|---|
| 00 | [导读：这个项目在解决什么问题](00-intro.md) | 明确的问题定义和技术选型理由 |
| 01 | [环境准备与跑通第一个字幕](01-setup.md) | 一条命令出字幕，建立信心 |

> **阶段目标**：能说出「一个视频从输入到出字幕，中间经过了哪几步」。

## 怎么读效果最好

**1. 每篇都动手跑**
代码片段都标了文件名和行号范围。边读边打开对应文件，对照着看。

**2. 先看「为什么」再看「怎么做」**
每篇开头有一段「本篇要解决的问题」。跳过它直接看代码，会看得云里雾里。

**3. 别怕跳读**
03-06 是流水线，跳过任意一篇后面都还能读（但 02 建议先读）。

**4. 13 篇可以随时翻**
遇到莫名其妙的报错，先去 13 篇搜一下——很可能已经记在那儿了。

## 每篇的统一结构

为方便你快速定位，每篇都按这个骨架写：

```
1. 本篇要解决的问题     ← 为什么需要这一层
2. 前置知识             ← 读之前该会什么
3. 核心概念             ← 关键设计决策，以及被否决的方案
4. 代码走读             ← 关键片段 + 逐段解释
5. 动手练习             ← 改点东西，验证理解
6. 小结                 ← 3 句话总结 + 下一篇预告
```

## 关于这个项目

它最初是为一个很具体的需求写的：**把短剧素材批量做成带英文字幕的成品**。
所以你会发现很多设计都在照顾「批量、长时间运行、无人值守」这个场景：

- 进度必须看得见（否则 40 分钟的批量任务让人以为卡死）
- 出错要能定位到具体哪个文件
- 一个文件失败不能拖垮整批

这些约束塑造了现在的架构。理解了它们，你就理解了所有"为什么这么写"。
